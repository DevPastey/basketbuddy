# BasketBuddy

BasketBuddy is a mobile-first Expo application built with Expo Router, React Native, Clerk authentication, NativeWind, and EAS. It is set up as a clean starter foundation for a polished consumer app: authenticated routes, social sign-in plumbing, native builds, web support, typed routes, and a Tailwind-powered styling workflow.

## Overview

BasketBuddy uses Expo Router for file-based navigation and Clerk for authentication. The current app shell includes:

- Auth-protected home routes under `src/app/(home)`.
- Sign-in routing under `src/app/(auth)`.
- Clerk session storage through `expo-secure-store`.
- NativeWind and Tailwind configuration for utility-first styling.
- Android, iOS, and web targets through Expo.
- EAS profiles for development, simulator, preview, and production builds.

## Prerequisites

Install the following before running the app:

- Node.js 20 or newer.
- npm, which is used by this repo's `package-lock.json`.
- Expo CLI through `npx expo`.
- Android Studio for Android builds or local emulation.
- Xcode for iOS builds on macOS.
- A Clerk application with Expo/mobile authentication enabled.

## Environment Variables

Create a `.env` file in the project root:

```bash
EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_your_clerk_publishable_key
```

The app reads this value in `src/app/_layout.tsx` and will throw an error during startup if it is missing.

Keep secrets out of source control. Only use `EXPO_PUBLIC_` variables for values that are safe to expose to the client bundle.

## Getting Started

Install dependencies:

```bash
npm install
```

Start the Expo development server:

```bash
npm run start
```

Then choose a target from the Expo terminal UI:

- Press `a` to open Android.
- Press `i` to open iOS.
- Press `w` to open web.
- Scan the QR code with a development build or Expo-compatible client.

## Project Structure

```text
basketbuddy/
|-- android/                  # Native Android project generated by Expo
|-- assets/                   # App icons, splash assets, and images
|-- src/
|   |-- app/                  # Expo Router routes and layouts
|   |   |-- (auth)/           # Public authentication routes
|   |   |-- (home)/           # Signed-in application routes
|   |   `-- _layout.tsx       # Root providers and navigation shell
|   |-- componenets/          # Component directory currently present in the repo
|   `-- hooks/                # Shared React hooks
|-- app.json                  # Expo app configuration
|-- eas.json                  # EAS build profiles
|-- global.css                # NativeWind global stylesheet
|-- tailwind.config.cjs       # Tailwind configuration
`-- package.json              # Scripts and dependencies
```

Note: the repo currently uses `src/componenets`. If you later standardize the spelling to `src/components`, update imports at the same time.

## Authentication

Clerk is initialized in the root layout:

```tsx
<ClerkProvider publishableKey={publishableKey} tokenCache={tokenCache}>
  {/* app routes */}
</ClerkProvider>
```

The `(home)` route group checks Clerk auth state before rendering protected screens. Signed-out users are redirected to `/(auth)/sign-in`.

Social auth work lives in `src/hooks/UseSocialAuth.ts` and is intended to support:

- Google OAuth
- GitHub OAuth
- Apple OAuth

Make sure each provider is enabled in the Clerk dashboard before exposing it in the UI.

## Running on Devices

For Android:

```bash

```

For iOS:

```bash

```

For web:

```bash
npm run web
```

Because this project includes native modules such as Clerk, SecureStore, WebBrowser, and Expo Dev Client, prefer a development build when testing native behavior.

## Builds with EAS

The project includes these EAS profiles:

| Profile | Purpose |
| --- | --- |
| `development` | Internal development build with dev client enabled. |
| `ios-simulator` | Development build for the iOS simulator. |
| `preview` | Internal preview distribution. |
| `production` | Production build with auto-incrementing versions. |

Example build commands:

```bash
npx eas build --profile development --platform android
npx eas build --profile ios-simulator --platform ios
npx eas build --profile preview --platform all
npx eas build --profile production --platform all
```

## Code Quality

Run linting before opening a pull request:

```bash
npm run lint
```

Recommended development habits:

- Keep route-specific logic close to the route group that owns it.
- Move reusable behavior into `src/hooks`.
- Keep shared UI components small, typed, and easy to compose.
- Prefer NativeWind utilities for styling unless a component truly needs `StyleSheet`.
- Avoid committing generated local state such as `.expo/` or environment files.

## Troubleshooting

### Missing Clerk Publishable Key

If the app fails with `Add your Clerk Publishable Key to the .env file`, confirm that `.env` exists and includes:

```bash
EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY=pk_test_your_clerk_publishable_key
```

Restart the Expo server after changing environment variables.

### Native Module or Build Issues

Clear Expo state and restart:

```bash
npx expo start --clear
```

If native dependencies changed, rebuild the development client:

```bash
npm run android
```

or:

```bash
npm run ios
```

### OAuth Redirect Issues

Check the following:

- The app scheme in `app.json` is `basketbuddy`.
- The OAuth provider is enabled in Clerk.
- Redirect URLs are configured in Clerk for the platform being tested.
- You are testing in a development build when validating native OAuth behavior.
